# Backpeer

Зашифрованные бэкапы на компьютерах других людей.

Backpeer сохраняет ваши файлы в зашифрованном виде на машинах других
пользователей и отдаёт взамен место на вашем диске. Файлы делятся на
фрагменты с избыточностью по Риду–Соломону, поэтому сеть сохраняет их
доступными, даже когда отдельные машины уходят, и сама чинит недостающие
фрагменты.

**Статус: ранняя разработка.** Проект на этапе MVP: форматы и API ещё
меняются, внешнего аудита безопасности не было, установочных сборок нет.
Код — рабочий материал, а не готовый продукт.

*[English version](README.md).*

## Как это устроено

- **Шифрование без знания ключа (zero-knowledge).** Всё шифруется на вашей
  машине до отправки: XChaCha20-Poly1305 для данных, Argon2id для паролей,
  Ed25519 для подписей, BLAKE2b для хэшей (libsodium через FFI). Хранители
  держат непрозрачные фрагменты и не видят ни содержимого, ни имён файлов.
- **Избыточность вместо копий.** Каждый сегмент бэкапа делится на `n = 20`
  фрагментов и читается из любых `k = 10`. Потерянные фрагменты координатор
  ставит в очередь ремонта, и сеть восстанавливает их сама.
- **Гибридная архитектура.** Координатор хранит метаданные, размещение,
  аудиты и репутацию узлов. Зашифрованные фрагменты идут напрямую между
  клиентом и хранителями — по TCP, через пробивание UDP или relay, в канале
  Noise XX.
- **Два фоновых процесса на клиенте.** `node` — демон хранителя, `agent`
  делает бэкапы по расписанию; настольное приложение — интерфейс к их
  локальным API.

Демон хранителя — обычный бинарник на Dart и работает без графической
оболочки, в том числе на NAS и одноплатных компьютерах.

## Структура репозитория

| Путь | Пакет | Что это |
|---|---|---|
| `packages/core` | `core` | Шифрование, erasure coding, чанкинг, форматы данных, сеть |
| `packages/protocol` | `protocol` | Схемы Protobuf и сгенерированный код |
| `packages/cli` | `cli` | Консольный клиент |
| `packages/daemon_kit` | `daemon_kit` | Общий код демонов: локальный API, журнал, блокировка папки |
| `packages/node` | `node` | Демон хранителя |
| `packages/agent` | `agent` | Агент бэкапа: расписание, проверка, восстановление |
| `packages/coordinator` | `coordinator` | Сервер координатора |
| `packages/relay` | `relay` | Relay для узлов без входящих соединений |
| `apps/app` | `app` | Настольное приложение (Flutter) |
| `test-vectors` | — | Тестовые векторы форматов и протокола |

Все пакеты, кроме `apps/app`, — чистый Dart без Flutter.

## Сборка

Нужны [FVM](https://fvm.app), [melos](https://melos.invertase.dev) и
[lefthook](https://lefthook.dev); версия Flutter зафиксирована в `.fvmrc`.

```sh
fvm install          # Flutter и Dart из .fvmrc
lefthook install     # git-хуки: форматирование, анализатор, правило зависимостей
melos bootstrap      # зависимости всех пакетов
melos run check      # форматирование, анализатор и тесты
melos run build-exe  # cli, node и agent в build/bin/<ОС>-<арх>/
```

Команды `flutter` и `dart` запускаются через `fvm flutter ...` и
`fvm dart ...` либо напрямую из `.fvm/flutter_sdk/bin`. Пакеты Linux (AppImage,
`.deb`, `.rpm`) собирает `tool/linux_package/build.sh`; приложение и `.dmg` под
macOS — `melos run macos:build` на Mac с Xcode.

Координатору нужен PostgreSQL; настройки — YAML-файл и переменные
`FS_COORDINATOR_*`.

## Безопасность

Zero-knowledge — цель устройства, и код, который её реализует, открыт для
проверки, но независимого аудита ещё не было. Не держите в Backpeer
единственную копию того, что боитесь потерять.
